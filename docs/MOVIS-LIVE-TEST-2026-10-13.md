# MOVIS 실제 GPT 업무 테스트 — 2026-10-13

실행 모델: 현재 계정 기본 모델 `gpt-6.1-sol`. 가짜 응답을 넣지 않고 실행 중인 MOVIS 브리지와 실제 GPT를 사용했다.

| 고객·주문 배송정보 동시 수정 | 서로 다른 두 확인 미리보기 | 통과 |

최초 자동 판정은 10개 통과였지만 답변을 직접 검토하자 마지막 시나리오에서 화면을 열지 않고 ‘열었다’고 표현한 문제를 발견했다. 도구 결과에서 이동 미실행을 GPT에게 전달하도록 수정한 뒤 같은 요청을 실제 GPT로 재실행해, ‘확인 대기 중이라 아직 열지 못했다’는 답변을 확인했다. 변경은 자동 저장하지 않았다.

## 실제 운영 자료 읽기 검증

실제 상품 1건의 ID·이름·재고·도매가만 읽어 GPT에 조회와 2개 금액 계산을 요청했다. 재고 및 계산 결과를 DB 값과 대조해 통과했다. 고객·주문·이미지 정보는 이 시험 입력에 포함하지 않았다. 실제 상품 상세 결과는 로컬 테스트 산출물에만 보관한다.

## 범위와 제한

10개 시나리오는 업무 자료를 가상 데이터로 구성하되 GPT와 브리지는 실제 연결했다. 네트워크에서 POS DB 쓰기와 외부 서비스 접근을 차단했다. 실제 운영 자료 시험은 상품 1건의 조회·계산에 한정했다. 운영 DB 저장, 송장 발급, 스마트스토어 전송은 이번 실사용 시험으로 검증하지 않았다. 전체 자연어 요청의 무오류를 의미하지 않는다.

재현: `node tests/movis-business-live.mjs`, 단일 사례는 `MOVIS_SCENARIO=memo-and-navigation` 환경변수 사용. 실제 계정 구독 사용량을 소비하므로 기본 단위 테스트와 분리한다. 실제 상품 조회는 `node tests/movis-real-readonly.mjs`로 별도 실행한다.


## 실제 화면 확인

운영 빌드를 브라우저에서 열고 DB 응답만 가상 자료로 격리한 상태에서 실제 GPT로 배송정보 변경을 요청했다. 확인창 제목·전화번호·주소가 요청과 일치했으며, 취소 후 모달이 닫혔다. DB 쓰기 시도 0건, 페이지 JavaScript 오류 0건이었다. 초기 진입 직후 입력 시도는 전송 비활성으로 두 차례 실패했으며, 연결·초기 로딩 완료 후 재시도는 통과했다. 초기 입력 유실 원인은 이 시험에서 확정하지 않았다.

결과 산출물은 tests/.artifacts/live-business-scenarios.json, live-business-memo-and-navigation.json, live-real-readonly.json, live-ui-result.json, live-order-confirm.png에 저장한다. 테스트 산출물에는 실제 상품 정보가 포함될 수 있어 GitHub에 커밋하지 않는다. 일반 회귀 테스트는 74개 통과했다.


## 추가 변수 검증 및 화면 개선

실제 GPT + 가상 POS 자료로 오타, 음수 재고, 잔량 초과 입고, 발주 수량 누락, 수정 취소 의도, 중복 발주번호, 메모에 포함된 명령문, 동일 상품의 두 번째 입고 행, 부분 로딩 재고 합계를 시험했다. 9개 모두 기대한 조회·거부·확인 대기 결과를 냈다. 운영 DB 변경은 없다. 재현 스크립트: `tests/movis-variable-live.mjs`.

초기 입력 시험의 시작 연출 중에는 콘텐츠가 `inert` 상태다. 이때 자동화 fill 호출의 빈 입력을 기존 판정이 통과로 분류했던 오류를 바로잡았다. 시작 화면 종료를 기다린 뒤 즉시 입력하는 조건으로 재시험했으며, 유지 여부를 기대 문자열과 직접 비교한다.

상단 모델·플랜·사용량·연결 상태를 구획이 있는 패널로 정렬하고 플랜 글자 크기를 통일했다. 대화 최대 폭은 1200px, 말풍선 사이 간격은 화면 폭에 따라 24~30px이며 내부 여백·본문 행간·처리 결과 위치를 함께 조정했다.

Chromium에서 1920×1080, 1536×1080, 1366×768, 900×1080, 768×1080, 390×844, 360×844를 검증했다. 가로 넘침과 상태 패널 겹침 없음, 모델 선택과 연결 설정 열기/닫기 통과. 1366 및 390에서 기존 메시지 등장·스트리밍·호버/터치 시험도 통과했다. 모바일은 터치 및 reduced-motion 조건을 사용했다. Windows 표시 배율 125/150%, Safari와 실물 모바일은 이번 시험에서 확인하지 않았다.
