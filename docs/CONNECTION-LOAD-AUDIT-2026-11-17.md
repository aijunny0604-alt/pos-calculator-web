# 연결 장애와 조회 부하 점검

## 확인한 사실과 한계

- 운영 프로젝트 재시작 이후 주문·상품·거래처의 읽기 응답과 데이터 존재를 확인했다. 전체 데이터 무결성 또는 복원 성공의 전수 검증은 아니다.
- 디스크 I/O 예산 소진 경고와 장애 직전 메모리 압박이 관찰됐다. Infrastructure의 I/O 잔여량은 최근 기간 최저치일 수 있으며 현재 잔여량으로 단정하지 않는다.
- 재시작 이후 Query Performance에서 실시간 변경 감시가 집계 처리 시간의 가장 큰 비중이었다. 쿼리 시간 비중은 디스크 I/O 소비 비중이 아니며, 재시작 이전 장애 원인을 입증하지 않는다.
- 보안 진단의 오류 7건·경고 27건은 별도 미해결 사항이다. 데이터 접근 정책과 인증의 단계적 전환은 SECURITY-SETUP.md를 따른다. 이번 변경에서 운영 권한은 수정하지 않았다. 외부 침해가 장애 원인이라는 증거는 확보하지 못했다.

## 적용한 변경

- 화면이 숨겨졌을 때 5분 간격 전체 주문·장바구니 조회를 미룬다. 화면 복귀 시 5분 이상 지난 경우 다시 읽는다.
- 전체 조회가 겹쳐 실행되지 않도록 막고, 화면 복귀 때 장바구니 중복 조회를 제거했다.
- 실시간 변경 뒤 늦게 도착한 장바구니 스냅샷이 최신 상태를 덮지 않도록 보호한다.
- 업체 주문의 실시간 구독·30초 보완 조회, 스토어 신규 주문 감시·알림음은 유지한다.
- 인터넷 오프라인은 즉시, 핵심 자료 읽기의 연속 서버·권한 오류 또는 네트워크 실패는 누적 2회부터 안내한다. 같은 자료의 정상 응답으로 실패 기록을 지우며 다른 자료의 성공으로 오류를 숨기지 않는다.
- 저장 요청은 자동 재시도하지 않는다. 저장 결과가 불확실하면 중복 처리 전 내역을 확인하도록 안내한다.

## 검증

- 연결·실시간 병합·전체 거래 자료 페이지 처리 테스트 9개 통과.
- 주문 도착·스토어 주문 보기·품절 알림 테스트 22개 통과.
- 모바일 Chromium에서 가상 API 응답으로 오프라인·재연결·503 안내 및 자동 복구를 검사했다. 실서버 장애를 다시 일으키거나 실제 주문을 생성하지 않았다.
- 주문 상세는 1920/1440/390/360 너비에서 상품명·수량, 화살표·키보드·스와이프, 편집 중 이동 보호를 검사했다.
- 배포 빌드 통과. 기존 큰 청크 및 번들 설정 경고는 남아 있다.

## 남은 점검

실사용 시간대의 I/O·메모리·쿼리 통계를 비교해야 개선 효과를 정량적으로 판단할 수 있다. 이번 변경만으로 서버 중단 재발 방지나 보안 조치 완료를 보장하지 않는다.
