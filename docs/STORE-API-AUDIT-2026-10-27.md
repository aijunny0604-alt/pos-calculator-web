# 스토어 기간 매출과 API 점검

## 기간 매출

- 스마트스토어 주문의 `기간 매출`은 선택한 한국시간 접수일 구간을 전체 페이지로 읽는다. 최근 200건 중심의 출고 모니터링 목록은 사용하지 않는다. 종료일은 다음 날 0시 미만으로 조회한다.
- 네이버 상품주문의 `remainPaymentAmount`를 우선 합산하고 없으면 클레임 없는 상품에 한해 최초 결제금액을 사용한다. 최초 금액 사용, 미확인 금액, 취소·반품과 미결제를 따로 표시한다. 종결 상태와 금액이 충돌하면 확인 대상으로 남긴다.
- 자료는 마지막 동기화 기준이다. 상품주문 단위 금액이므로 배송비·수수료·정산액을 별도로 합산하지 않으며, 누락된 동기화와 환불 진행에 따라 확정 정산과 다를 수 있다. 세무·정산 판단은 `정산·부가세`의 네이버 자료로 대조한다.
- 주문 요약과 CSV에서 대표 상품 한 건의 금액 대신 주문 상세와 동일한 주문금액 계산을 사용한다. 취소·미결제를 포함하는 기존 `오늘 매출`은 `오늘 접수 금액`으로 표시한다.
- 네이버는 상품주문별 최초·잔여 결제금액과 주문일을 제공한다: [상품 주문 정보 구조체](https://apicenter.commerce.naver.com/docs/commerce-api/current/schemas/%EC%83%81%ED%92%88-%EC%A3%BC%EB%AC%B8-%EC%A0%95%EB%B3%B4-%EA%B5%AC%EC%A1%B0%EC%B2%B4).

## 검증과 한계

- 실제 읽기 전용 조회: 네이버 문의, 일별·건별 정산, 수수료, 부가세 응답 정상. 상품 3건 및 옵션 14개 실시간 조회 정상. 실제 쓰기 요청은 보내지 않았다.
- 이번 달 동기화 주문 30건을 읽어 상품 금액 제공 여부를 확인했고, 주문일 비교가 가능한 30건의 네이버 주문일과 접수일은 한국시간 일자 기준 일치했다. 다른 기간이나 모든 주문에 대한 대사는 아니다.
- 모의 테스트: 발송 대기→발송→배송중, 제품 변경 확인·취소 및 모의 적용, 품절·재주문 추천, 모바일 연결·해제, 정산·부가세 조회, 취소·부분 반품·누락 금액과 날짜 경계. 1366×768, 390×844, 360×800 Chromium에서 매출 화면과 가로 넘침을 확인했다.
- 전체 자동 테스트 226개 중 225개 통과, 실패 0개, 환경 의존 1개 건너뜀. 620건 샘플의 전체 페이지 조회와 누락·취소 금액 계산을 별도로 검증했다.
- 실제 네이버 발송·발주확인·취소·상품 변경, 장기간 전체 매출과 네이버 관리자 대사, 실물 iOS/Android 및 Safari는 시험하지 않았다.
- 문의와 정산·부가세 API 화면은 매장 PC의 `127.0.0.1` 연결 전용이다. 휴대폰 상품 제어용 연결 코드로 문의·정산 자료를 조회하지 않는다. 화면에 이 조건을 표시했다.
- 2026-10-28 배포 전 재검증: 자동 테스트 225개 통과·1개 건너뜀, 1366·390·360 매출 화면 및 발송 상태 샘플 통과. 꺼져 있던 매장 PC 조회 연결을 재실행하고 문의·정산·수수료·부가세 읽기 응답을 확인했다.
