# MOVE POS 운영·코드 점검 — 2026-10-13

## 평가

업무 기능과 계산 유틸, MOVIS 변경 확인·원본 재검증은 상당 부분 갖춰져 있다. 그러나 다중 사용자 업무 시스템으로서 접근 통제, 원자적 재고 변경, 장애 상태 표현은 보강이 필요하다. 빌드·단위 테스트 성공을 전체 업무의 안전성 보증으로 해석하지 않는다. 과거 문서의 점수는 현재 품질을 대표하지 않는다.

이 문서는 저장소 코드 점검 결과다. 운영 프로젝트의 상세 권한 메타데이터, 고객·주문 자료, 인증 정보는 공개 문서에 포함하지 않는다. 운영 DB 스키마·권한은 이번 수정으로 변경하지 않았다.

## 장애 조사와 범위

2026-10-13 KST에 정적 웹 페이지는 응답했으나 공용 DB 읽기가 시간 초과하여 여러 기기가 함께 오프라인을 표시했다. Supabase 로그에서 statement timeout을 확인했다. Disk IO 예산 경고도 수신되었으나, 경고만으로 정확한 유발 쿼리나 예산 완전 소진을 확정할 수 없다.

약 21:06 프로젝트 재시작 후 약 21:13에 주문·상품·거래처·저장 장바구니·결제 자료의 제한된 읽기 요청이 모두 HTTP 200으로 복구되었다. 공개 POS 화면에서도 ONLINE 및 자료 로딩을 확인했다. 업무 자료 생성·수정·삭제는 하지 않았다. 재시작은 복구 조치이며 재발 원인의 영구 제거를 의미하지 않는다.

MOVIS 로컬 브리지와 공용 POS DB는 별개다. PC를 끄면 그 PC의 브리지가 종료된다. 다른 기기의 POS 주문·재고까지 함께 중단된 현상을 로컬 브리지 종료만으로 설명할 수 없다. GPT 연결 자체가 장애 원인이라는 증거는 확보하지 못했다.

## 수정의 한계

- 초기 연결 복구와 SDK 채널 재연결을 개선했지만 ONLINE 배지는 모든 API가 지금 건강하다는 보장이 아니다.
- MOVIS는 여전히 질문마다 여러 보관함을 조회한다. 이번 변경은 순간 동시 부하를 줄인다. 후속으로 질문별 필요한 테이블/필드만 요청하고, 정합성 요구를 충족하는 캐시를 설계해야 한다.
- 운영 권한, Gemini 비밀 키 보관 방식, 백업/복구 체계, 재고 트랜잭션은 아직 해결되지 않았다.
- 일반 POS의 변경 실패 처리 및 결제·재고 정합성은 스테이징에서 동시성·중단·재전송 시나리오를 검증해야 한다. 운영 자료로 파괴적 테스트하지 않았다.
- 소스 수정과 운영 배포는 다르다. 이 점검 문서만으로 GitHub Pages나 기존 Windows 배포 ZIP에 반영되었다고 간주하지 않는다.

## 검증

- 격리된 로컬 MOVIS 브리지에서 `MOVIS_TEST_URL`을 설정하여 Node 회귀 검사 83개 통과, 실패/건너뜀 0개.
- 프로덕션 빌드 성공. 큰 청크 및 정적/동적 import 혼용 경고가 남아 있다.
- 격리 브라우저에서 초기 OFFLINE 후 모의 서버 복구 시 새로고침 없이 ONLINE으로 전환됨을 확인했다. 정상 의존성 재설치도 peer dependency 우회 없이 통과했다.
- `npm audit --omit=dev`: moderate 2개(exceljs → uuid), high/critical 0개. 전체 의존성: moderate 4개, high 5개. 숫자는 의존성 경로를 포함하므로 서로 다른 공격 9건이라는 뜻은 아니다. 강제 메이저 변경은 하지 않았다.
- 운영 화면의 주문·재고·거래처·명세서·매입 발주를 읽기 전용으로 확인했다. 변경한 소스의 운영 쓰기 검증 및 실제 두 PC 간 실시간 갱신 검증은 수행하지 않았다.
- 재현 방법과 상세 한계는 [TESTING.md](TESTING.md)를 따른다.

## 다음 작업 순서

1. 비밀정보를 서버에 이관하고 승인된 직원 인증을 준비한 뒤 RLS를 전환한다. 기존 사용자에게 로그인 경로를 배포하기 전에 익명 권한부터 차단하지 않는다.
2. 별도 환경에서 주문·재고·결제의 트랜잭션과 중복 방지를 구현하고 경쟁 조건을 검증한다.
3. 모든 주요 목록의 페이지네이션 및 실패 표시를 통일한다.
4. 느린 쿼리·IO 사용량·동시 요청 수를 관찰하여 조회 최적화 후 필요한 컴퓨트 용량을 결정한다. 재시작 반복을 해결책으로 사용하지 않는다.
5. 백업 생성뿐 아니라 복원 연습까지 검증하고 책임자·보관 주기·복구 목표를 기록한다.
