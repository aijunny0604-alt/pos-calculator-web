# MOVIS Intelligence v2

MOVIS는 매장 PC에서 실행되는 Codex App Server를 통해 ChatGPT 구독 사용량으로 작동합니다. 새 브라우저는 계정의 권장 모델을 자동 선택합니다. 직접 선택한 모델은 유지하며, 추론 강도는 지원 시 `high`입니다. API 키 과금으로 전환하지 않습니다.

## 운영 사이트와 배포

운영 주소: https://aijunny0604-alt.github.io/pos-calculator-web/

최근 웹 배포: **2026-10-13 안정화 버전**. [소스·배포 커밋 및 검증 기록](DEPLOYMENT-2026-10-13.md). 이전 Windows ZIP의 로컬 웹 파일은 별도로 갱신해야 하며, 공용 웹 배포가 설치 파일을 자동 교체하지 않는다.

2026-10-08 업그레이드 소스는 `master`, 정적 배포본은 `gh-pages` 루트를 사용합니다. 운영 사이트에서도 이 매장 PC의 `Start-MOVIS.cmd`를 먼저 실행해야 합니다. 기존 화면이 남으면 Ctrl+Shift+R로 새로고침하세요. 브라우저가 로컬 네트워크 접근을 요청하면 허용하고, MOVIS 상단 Codex 연결에서 연결 상태를 확인합니다. 정적 웹사이트만으로는 구독 모델이 실행되지 않습니다.

배포 절차: `npm run test:movis` → `npm run build` → `dist` 전체(숨김 파일 `.nojekyll` 포함)를 `gh-pages`에 커밋·push → GitHub Pages 최신 빌드 `built`와 운영 index.html 번들 해시 일치 확인. 소스만 master에 합치면 운영 정적 파일은 갱신되지 않습니다.

## 시작 애니메이션

MOVIS 메뉴에 들어갈 때 코어 점등, 원근 격자, 스캔 라인과 로고가 약 2.4초 동안 나타납니다. **바로 시작** 버튼 또는 Escape로 건너뛸 수 있으며, 2026-10-12부터 OS의 동작 줄이기 설정과 무관하게 실행합니다. WebGL을 사용할 수 없으면 CSS 회전 코어로 대체합니다. 화면 진입 연출이며 실제 인증·자료 조회 성공을 의미하지 않습니다. 실제 연결은 상단 Codex 연결 상태로 확인합니다.

## 실행

Node.js와 Codex 데스크톱 앱이 설치된 PC에서 `Start-MOVIS.cmd`를 실행합니다. 소스 체크아웃에서는 먼저 `npm ci`, `npm run build`를 실행하세요. 빌드된 배포 패키지는 추가 패키지 설치 없이 실행할 수 있습니다.

프로그램은 `http://127.0.0.1:43127/pos-calculator-web/`에서 열립니다. 기존 POS와 같은 Supabase 데이터를 사용합니다. localhost는 기존 GitHub Pages와 브라우저 저장 공간이 다르므로 로컬 전용 대화·기기 설정은 자동으로 옮겨지지 않습니다.

상단 **Codex 연결**에서 계정 연결, 모델, 남은 한도를 확인합니다. 최초 실행은 현재 PC의 Codex 로그인 캐시를 별도 런타임에 재사용합니다. 연결이 만료되면 **ChatGPT 로그인 → 로그인 창 열기 → 연결 새로고침**을 누르세요. API 키 로그인은 허용하지 않습니다. 토큰과 런타임 로그는 `.movis-runtime/`에만 저장되며 Git이나 배포 ZIP에 포함하지 않습니다.

브리지는 IPv4 loopback에만 바인딩합니다. 허용된 웹 Origin, 임의 세션 토큰, Host 검사로 연결을 제한합니다. GitHub Pages에서 새 버전을 배포해 사용할 때도 같은 PC의 브리지가 켜져 있어야 하며, 브라우저가 요청하면 로컬 네트워크 접근을 허용해야 합니다. 휴대폰에서 매장 PC로 원격 접속하는 기능은 포함하지 않습니다.

## 지능과 자료

- 모델이 제공된 POS 도구를 선택하고 결과를 바탕으로 다음 조회를 이어갑니다. 이전의 키워드 기반 강제 분기, 답변에서 주문을 합성하는 코드, 가짜 검색 답변은 제거했습니다.
- 서버가 살아 있는 동안 Codex 대화 상태를 유지합니다. 재시작·모델 변경 시 화면의 최근 대화(최대 200개, 전송 크기 상한 내)를 배경 자료로 전달합니다. 무제한 장기 기억을 보장하지 않습니다.
- 요청마다 브리지 연결을 먼저 확인하고 POS 22개 테이블을 페이지 단위로 새로 읽습니다. 2026-10-13 안정화 소스는 요청당 테이블 조회 동시성 2, 전체 조회 60초 제한과 사용자 취소를 적용합니다. 테이블당 최대 50,000행에서 멈추면 부분 자료로 표시합니다. 저장소는 별도 `listImageFiles`로 폴더별 조회하므로 총 23개 자료 범주가 제공됩니다.
- 상품, 거래처, 판매 주문, 견적, 매입 발주, 매입 단가, 입금·미수, 반품, 스마트스토어, 사업자등록증, 매입 증빙, 공급처 원장, 포장, 완불 표시, 주문 감사 기록, 운영 설정, 이미지 파일을 조회할 수 있습니다.
- `inspectLibraryImage`는 실제 조회한 POS 레코드/이미지 저장소에 존재하는 HTTPS 이미지만 모델에 전달합니다. 사진 첨부는 5MB 이하 JPG·PNG·WebP입니다. PDF 원문 추출과 PC 문서 폴더 탐색은 포함하지 않습니다.
- 셸·파일 수정·개발 플러그인은 무비스 런타임에서 끕니다. 업무 도구의 쓰기는 기존 POS 확인창에서만 수행합니다.

## 오류 방지와 한계

1. 도구 인자의 자료형·필수값·범위와 업무 목적을 검사합니다. 발주를 재고 증가/판매로 바꿔 실행할 수 없습니다.
2. 원본 조회 없는 변경 미리보기, 중복 대상, 음수 재고, 잘못된 수량, 단가×수량과 총액 불일치를 거부합니다.
3. `verifyWork`는 도구 실패·조회 근거·자료 누락·대기 변경을 점검합니다. 답변 아래에서 실제 결과를 펼쳐볼 수 있습니다. 이는 AI가 쓴 모든 문장의 사실 정확성 보증이 아닙니다.
4. 확인 클릭 시 대상 재고·가격·거래처·주문을 다시 조회하여 미리보기 당시 값과 다르면 중단합니다. 같은 화면에서 중복 클릭을 막습니다.
5. 기존 Supabase 쓰기 API를 사용하므로 실행 전 검사와 DB 저장 사이의 다른 기기 변경까지 원자적으로 막는 것은 아닙니다. 여러 테이블에 걸친 완전한 트랜잭션·전역 idempotency는 별도 DB 마이그레이션이 필요합니다.
6. 실제 운영 데이터에 쓰는 테스트는 하지 않았습니다. 실제 데이터는 읽기 연결만 확인하고 변경 시나리오는 가상 데이터의 미리보기까지만 검증했습니다.

브라우저 기본 TTS, 자동 음성 전송, MOVIS 효과음은 제거했습니다. 고품질 음성 API를 몰래 추가하지 않습니다.

## 다른 PC와 모바일

- 다른 Windows PC: Node.js와 Codex를 설치하고 ChatGPT 로그인 후 이 실행 패키지의 `Start-MOVIS.cmd`를 실행합니다. 운영 사이트는 그 PC의 localhost 브리지에 연결합니다.
- 같은 ChatGPT 계정은 구독 사용량을 공유합니다. POS 업무 데이터는 같은 DB를 사용하며 대화 기록은 브라우저별로 저장됩니다.
- `Install-MOVIS.cmd`를 실행하면 현재 Windows 사용자에게 설치합니다. Windows 로그인 시 자동 연결은 설치 중 Y를 선택한 경우에만 등록합니다. 이후 바탕화면 `MOVE POS`로 열면 됩니다. 설치 없이 사용하는 경우에는 `Start-MOVIS.cmd`를 실행하세요.
- 2026-10-13 모바일 요청이 재개되었고, 사용자마다 각자 계정을 연결하기로 확정했습니다. 모바일 웹의 사용자별 구독 연동은 공식 앱 등록·호스팅형 구독 사용 승인과 HTTPS 백엔드가 필요하여 아직 제공하지 않습니다. 현재 패키지를 모바일에 설치할 수는 없습니다.


## 2026-10-12 — 모델과 사용량 제어

상단에서 계정의 실제 `model/list`에 반환된 GPT 모델을 선택합니다. 응답 진행 중에는 전환을 잠그며, 변경 후 새 엔진 대화에 최근 문맥을 넘깁니다. 계정에서 제공되지 않는 모델을 임의로 추가하지 않습니다.

사용량은 `account/rateLimits/read`가 반환한 계정 전체 한도입니다. 한도 그룹과 기간별 **사용 % / 남은 % / 게이지**를 표시하고 초기화 시각은 게이지 도움말에서 확인합니다. 10초 주기로 갱신하고 응답 종료·화면 복귀 시 즉시 조회합니다. 과금 서버 반영 지연이 있을 수 있으며 순간별 토큰 계측기는 아닙니다. 조회 실패 시 마지막 값에 갱신 실패를 표시하며, 미제공 값은 0%로 표시하지 않습니다.


## 최종 적용 범위

PC 전용 ChatGPT 구독 연결, 계정 제공 GPT 모델 선택, 사용량 퍼센트·게이지, 대화 문맥과 POS 자료 조회, 변경 전 자체 검증, 3D 코어·진입 연출을 유지합니다. 저품질 음성/TTS는 제거 상태입니다. 운영 접속에는 이 PC의 Start-MOVIS.cmd 실행과 브라우저 로컬 네트워크 권한이 필요합니다.


## 다른 PC 설치 (2026-10-13)

Node.js LTS와 Codex 데스크톱 앱이 있는 Windows PC에서 ZIP 전체를 풀고 `Install-MOVIS.cmd`를 실행하세요. 설치 후 `MOVE POS`를 열어 본인의 ChatGPT 계정으로 연결합니다. 이 ZIP에는 제작 PC의 로그인 토큰·대화·실행 로그가 포함되지 않습니다. 각 Windows 사용자/PC의 인증은 별개이며, 한 Windows 계정을 여러 사람이 공유할 때의 계정 격리는 지원하지 않습니다.


2026-10-13 추가: 무비스 연결 설정 안에서 Windows 설치 ZIP을 직접 선택해 다운로드할 수 있다. 화면 진입만으로 다운로드·설치·로그인 창을 실행하지 않는다. 신규 설치의 Windows 자동 시작은 기본 해제이며 사용자가 선택한다. 이 매장 PC에서 앞서 명시적으로 설정한 자동 시작은 유지한다.


## 주문 배송정보와 도구 접근 (2026-10-13)

무비스는 등록된 전체 POS 업무 도구를 매 요청마다 전달받습니다. `listAvailableTools`는 실제 전달된 도구명·설명·변경 확인 필요 여부를 반환합니다. 전체 자료 보관함 조회와 해당 자료를 변경하는 기능은 별개입니다. 매입 발주 등록 등 아직 구현하지 않은 변경을 수행 가능하다고 표시하지 않습니다.

- `updateOrderContact`: 정확한 주문번호로 기존 주문의 연락처·배송주소를 수정합니다. 생략한 필드는 유지하며 빈 문자열은 삭제 미리보기로 표시합니다.
- 주문 검색 결과에도 주문에 저장된 연락처·주소를 제공합니다. 거래처 기본정보 변경이 기존 주문에 소급 적용되는 것은 아닙니다. 둘 다 요청하면 각각 확인을 준비합니다.
- 변경 전 주문 원본과 현재 값이 다르면 중단합니다. 저장 응답 및 DB 재조회가 일치해야 완료를 표시하고 주문 내역 화면을 갱신합니다. DB 저장과 재조회 사이에 통신이 끊기면 저장되었을 수 있다는 안내를 표시합니다.
- 기존 상품·거래처 등록/수정, 가격·재고 변경, 주문 생성·메모·입금·반품 도구와 22개 자료 보관함을 유지합니다. 도구 목록 조회만으로 원본 조회 검증을 통과할 수 없습니다.
- 실제 고객 자료를 임의 변경하지 않고 가상 주문으로 도구 실행·저장 실패·재조회 불일치·동시 변경 검증을 수행했습니다.


## POS 업무 도구 확장 (2026-10-13)

등록된 모든 도구는 매 요청의 실제 도구 목록으로 제공됩니다. 새 도구 16개는 사용자 확인 전에는 저장하지 않으며, 실행 직전 원본 대조·조건부 갱신·저장 후 재조회를 수행합니다. 이 도구들은 해당 보관함을 `readLibrary`로 먼저 조회해야 합니다.

| 영역 | 새로 직접 실행 가능한 작업 |
|---|---|
| 매입 발주 | 신규 발주 등록, 기본정보 수정, 정확한 품목 행의 입고 기록 |
| 공급처 장부 | 등록, 수정, 완료·되돌림, 개별 삭제 |
| 매입 단가 | 단가 이력 등록, 개별 이력 삭제 |
| 공급처 불량 반품 | 신규 등록, 기본정보 수정, 교환품 회수 기록 |
| 매입 증빙 | 날짜·공급처·문서종류·금액·메모 수정 |
| 사업자등록증 | 보관함 표시 이름 수정 |
| 저장 견적 | 연락처·주소·배송일·메모 수정 |
| 상품 | 분류·최소재고·메모 수정 |

입고·교환품 회수 기록은 발주/반품 장부에만 반영합니다. 상품 재고는 기존 재고 도구로 별도 요청·확인해야 합니다. 기존 판매 주문·거래처·상품 등록/수정·가격·재고·입금·고객 반품 도구와 원본 자료 조회는 유지합니다.

모든 주요 POS 화면 이동을 연결했습니다. `navigatePage`는 매입 발주·단가·공급처 장부를 포함합니다. 송장/명세서 출력, 파일 업로드·백업 복원, 외부 스마트스토어 전송, 설정 변경, 아직 전용 도구가 없는 복합 수정·삭제는 **해당 화면에서 이어서 처리**합니다. 화면 이동은 해당 업무의 실행 완료가 아닙니다. 모든 화면 동작을 무비스가 직접 실행하는 범용 조작 기능은 아닙니다.

검증: 가상 레코드로 16개 신규 도구의 미리보기→저장→재조회 및 충돌/실패 경로를 확인했습니다. 실제 DB 8개 영역에 0행 조회로 필드 존재 여부를 확인했습니다. 실제 주문·재고·장부는 테스트로 변경하지 않았습니다.


## 기능 점검·신뢰성 개선 (2026-10-13)

- 주문 메모·완불·고객 반품 도구는 검색으로 확인한 정확한 주문번호를 사용합니다. 잘못된 번호를 같은 고객의 다른 주문으로 대체하지 않습니다. 사용자가 번호를 직접 입력해야 하는 것은 아니며 무비스가 먼저 검색합니다.
- 거래처 조회·단일/일괄 수정에서 동명이인과 부분일치 다중 후보를 임의 선택하지 않습니다. ID를 지정했는데 없으면 이름으로 우회하지 않습니다.
- `getRecord`는 보관함 ID로 한 건을 확인합니다. `getSystemHealth`는 요청 시점의 접근 오류와 부분 로드를 진단합니다. 화면 이동·도구 목록·진단 자체는 데이터 변경 근거로 인정하지 않습니다. 변경 업무와 같은 종류의 자료를 조회해야 합니다.
- 하나의 응답에 변경 확인과 화면 이동이 함께 있으면 확인 대기를 보호하기 위해 화면 이동을 보류합니다. 확인을 마친 뒤 이동할 수 있습니다.
- 주문 메모는 저장 후 재조회하고 주문 목록 상태를 갱신합니다. 무비스의 완불 완료는 정산 잔액 재조회로 확인합니다. 입금 이력 저장 실패 시 정산 금액을 올리지 않으며, 이력 저장 후 정산 반영 실패는 부분 처리로 구분합니다.
- 빈 등록 응답과 지원하지 않는 작업을 성공으로 알리지 않습니다.

검증: 실패·충돌·잘못된 대상 재현을 포함한 73개 회귀 테스트 통과. 테스트는 가상 자료로 수행했으며 실제 주문·입금·재고를 변경하지 않았습니다. 모든 자연어 해석의 정확성을 보장하는 기능은 아니며, 정산의 여러 테이블 저장은 아직 단일 DB 트랜잭션이 아닙니다. 부분 처리 안내가 나오면 재실행 전에 정산 내역을 확인해야 합니다.
