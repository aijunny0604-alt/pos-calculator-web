# 레조 구경 검색·예약 알림과 AI 주문인식 레이아웃

## 레조 검색

레조 제품의 규격은 몸통 외경·길이·연결 구경 순서다. 기존 근접 규격 함수는 첫 숫자를 구경으로 취급해 `레조 100 200 63`에서 `레조 100 200 64`를 누락했다. 레조는 마지막 연결 구경만 ±1 후보로 허용하도록 구분했다. 몸통 외경과 길이는 입력값이 같아야 하며 소수 규격은 보정하지 않는다. 입력 숫자의 순서는 바꿀 수 있다.

- `레조 100 200 63` → `레조 100 200 64`
- `레조100 250 63` → `레조 100 250 64`
- 길이 200을 250으로 바꿔 검색하지 않는다.

정확 일치가 앞에 나오고 보정 후보에는 기존 ‘근접 규격’ 표시를 유지한다. 공통 수동 상품 선택에도 적용되며 주문·재고 쓰기의 자동 매칭 로직은 변경하지 않았다. 검색은 로컬 처리이며 추가 서버/API 조회가 없다.

## 모바일 AI 주문인식

입력 영역이 스크롤 밖에서 높이를 차지해 예약 알림과 함께 표시될 때 결과 영역을 0에 가깝게 줄이고 하단 버튼을 화면 밖으로 밀었다. 수정 전 390×700px 샘플에서 주문 버튼의 하단이 813px까지 내려간 것을 확인했다.

입력과 결과를 하나의 스크롤 영역으로 묶고 주문 버튼은 바깥에 유지했다. 단독 페이지의 하단 메뉴 여백은 AppLayout에서만 확보해 중복 여백을 제거했다. 예약 알림은 화면 높이의 35%를 넘으면 자체 스크롤되며 내용을 삭제하거나 숨기지 않는다.

제품 주문에서 여는 AI 창과 내부 설정·백업·수정 사유 창은 기존 ViewportModal을 사용한다. 부모 페이지의 transform·예약 알림 높이와 독립된 위치, visualViewport 높이·위치 반영, 기존 공통 입퇴장 애니메이션을 유지한다. AI 창 크기는 실제 보이는 화면을 기준으로 제한한다.

## 검증 범위

- 공통 검색 테스트: 기존 플랜지·자바라·직선·CH·소수·붙여쓰기 검색과 레조 ±1 및 잘못된 몸통 외경·길이 제외.
- 제품 주문 화면: PC 1440×900, 모바일 390×844에서 CH 및 레조의 목록·카드 검색과 근접 표시.
- AI 주문인식: 예약 5건 상태에서 1440×900, 390×844, 360×640, 390×420 각각 단독 페이지와 제품 주문 모달을 검증. 입력 분석, 결과 마지막까지 스크롤, 주문 버튼의 위치·다른 레이어 가림 여부, 내부 설정창 버튼 접근, 장바구니 담기를 확인했다.
- 운영 주문·재고를 쓰지 않는 로컬 샘플 및 무료 패턴 분석을 사용했다. 유료 AI API 호출 없이 확인했다. 420px 높이는 좁은 가용 화면을 모사한 것이며 실제 iOS/Android 키보드 동작을 검증한 것은 아니다.
