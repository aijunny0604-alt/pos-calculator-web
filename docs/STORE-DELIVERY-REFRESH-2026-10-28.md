# 네이버 배송완료 재확인

- 2026-10-28 실제 네이버 상품주문 34건을 읽기 전용으로 대조한 결과, 금액 차이는 없었고 8건은 네이버 `DELIVERED`, 저장된 상품 상태 `DELIVERING`이었다. 해당 주문의 대표 상태는 `shipped`였고 마지막 상세 조회는 42~186시간 전이었다.
- 기존 매장 PC `naver-sync-bridge/sync.js`는 네이버 변경 주문 이벤트가 도착했을 때 상세를 다시 조회한다. 네이버 변경 알림의 유형에는 배송완료 전용 항목이 없어 배송완료 이후 상세 상태가 갱신되지 않을 수 있다. 따라서 변경 알림만으로는 배송완료를 보장할 수 없다. [네이버 변경 상품 주문 내역 API](https://apicenter.commerce.naver.com/docs/commerce-api/current/seller-get-last-changed-status-pay-order-seller)
- `bridge/naver-delivery-refresh.mjs`를 매장 PC의 동기화 폴더에 함께 설치하고, 재시작 후 초기 1회와 이후 15분 간격으로 배송중 상품을 네이버 상세 API에서 재확인한다. 한 번에 최대 100건을 조회하고 재진입·중복 조회를 제한한다.
- 실제 네이버 응답의 상품주문번호·주문번호가 일치하고 상태가 배송완료 또는 구매확정일 때만 상품 상태를 갱신한다. 다른 마켓·취소·반품·진행 중 클레임은 제외하고, 금액과 나머지 저장 필드는 보존한다. 저장 중 다른 작업이 데이터를 바꾸면 조건부 업데이트를 중단하고 다음 주기에 재확인한다. 실제 네이버 발송·확인·취소 명령은 호출하지 않는다.
- 매장 PC 백업은 `tests/.artifacts/sync-before-delivery.mjs`에 보관했다. 운영 `sync.js`는 `--delivery-dry-run`으로 쓰기 없이 대상만 확인하고, `--delivery-refresh`로 상태만 1회 확인할 수 있다. 이 두 모드는 발주·발송·취소 큐를 실행하지 않는다.
- 적용 전 실제 읽기 미리보기: 배송중 후보 10건 중 8건 갱신 대상. 조건부 1회 갱신: 8건 변경, 경합 0건. 적용 후 재조회: 34건 모두 네이버 상태·금액 일치, 남은 배송중 2건은 네이버에서도 배송중.
- 운영 스토어 UI의 최근 1개월 단계 표시: 배송중 2건, 배송완료 33건. 재시작된 동기화 프로세스의 자동 재확인 로그에서 대상 2건을 확인하고 변경 0건임을 확인했다.
- 자동 테스트 233개 중 232개 통과, 1개 환경 의존 테스트 건너뜀. 취소·클레임·부분 배송, 잘못된 주문번호, API 실패 및 동시 수정 경합을 샘플로 검증했다. 15분은 재확인 간격이며 네이버 API와 PC 연결 상태에 따라 실제 반영은 더 늦어질 수 있다.

## 재설치 및 재검증

- 매장 PC 동기화 프로그램은 웹 정적 파일과 별도로 운영된다. 소스 저장소의 `bridge/naver-delivery-refresh.mjs`를 동기화 폴더에 복사하고, `python bridge/prepare-naver-delivery-sync.py 기존-sync.js 새-sync.js`로 변경본을 별도 파일에 생성한다. 원본을 백업하고 변경본을 검토한 후 교체한다. 이미 적용된 파일에는 다시 적용하지 않는다.
- 생성 도구는 지정된 코드 위치가 각각 한 번씩 있는 경우에만 작업하고, 기존 파일이나 이미 존재하는 출력 파일을 덮어쓰지 않는다. 2026-10-28 적용 전 파일에 변경을 적용한 결과가 현재 운영 `sync.js`와 줄바꿈을 정규화했을 때 동일한지 확인했다. 대상 버전이 달라 생성이 실패하면 차이를 검토한다.
- 재시작 뒤 `logs/sync-YYYY-MM-DD.log`의 `[배송상태 재확인]` 로그와 `node sync.js --delivery-dry-run`을 확인한다. 이 확인은 네이버에 실제 발송·취소 명령을 보내지 않는다.
- 재검증: 전체 자동 테스트 232개 통과·실패 0개·환경 의존 1개 건너뜀, 웹 프로덕션 빌드 성공. 실데이터 읽기 대조 34건에서 배송 상태 및 금액 차이 0건. 재조회 당시 배송중 2건은 네이버에서도 배송중이었다.
- 웹 UI에는 추가 변경이 없으므로 기존 GitHub Pages 정적 배포를 유지한다. 배송완료 보정은 매장 PC 동기화 프로그램에 이미 적용 및 재시작되어 있다.
