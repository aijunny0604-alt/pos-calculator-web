- 매장 `naver-sync-bridge/sync.js` 실행 프로세스와 heartbeat, DB 동기화 시각을 읽기 확인했습니다. 조회 시점 주문 커서는 2026-10-12 17:40 KST, 발주확인·발송·취소 대기열은 각각 0건이었습니다.
- 발주확인·방문수령·발송의 DB 저장 실패에도 성공 토스트가 나오던 경로를 수정했습니다. 저장된 행이 확인된 경우에만 성공 안내와 모달 닫기를 수행합니다.
- PAYED 상태의 raw_payload.claimStatus 취소·반품 요청도 전역 알림에 반영합니다. 같은 주문의 다른 클레임을 구분하고 새 주문이 미확인 취소 알림을 덮지 않게 했습니다.
- 실제 매장 브리지에서 취소승인 큐 처리기를 찾지 못했습니다. 미처리 큐를 등록하며 환불 확정을 약속하던 버튼을 판매자센터 열기로 변경했습니다. 실제 취소·환불을 이 앱에서 실행하지 않습니다.
- 내부 주문 전환 직전 주문·품목을 새로 조회합니다. 이미 전환/미결제/진행 중 클레임/불완전 품목/잘못된 수량·금액을 차단합니다. 같은 화면의 중복 전환을 잠그고 저장 후 연결 실패는 성공으로 표시하지 않습니다.
- MOVIS 연결 프로그램 재시작에 따른 401은 세션 재발급 후 한 번 복구합니다. 통신 실패/5xx/이미 시작된 응답은 재전송하지 않습니다. 인증 발급 중 취소된 업무는 보내지 않습니다.

## 검증과 남은 범위

`node --test tests/movis-*.test.mjs tests/store-safety.test.mjs` 30개 통과. 운영 주문을 전환·발송·취소하거나 재고를 변경하는 실험은 하지 않았습니다. 실제 네이버 API 쓰기 성공까지 검증했다는 의미는 아닙니다.

다른 PC가 동시에 동일 주문을 전환하는 경합과 POS 저장 이후 외부 주문 연결까지의 원자적 처리는 기존 DB 트랜잭션으로 보장되지 않습니다. 이번 패치는 화면 내 중복 및 최신 상태 검증을 보강한 것이며 DB 차원의 전역 중복 방지를 대체하지 않습니다. 연결 실패 메시지가 나오면 내부 주문을 확인하고 재전환하지 마세요.

동기화 bridge 파일·스케줄러·DB 스키마는 수정하지 않았습니다. 취소승인 자동화를 다시 도입하려면 공식 API 구현과 별도 검증이 필요합니다.
