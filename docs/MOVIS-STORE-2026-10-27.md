# 무비스 스토어 품절·재주문·문의

- 무비스 모델은 매장 PC의 Codex 연결이 반환한 계정별 모델 목록을 사용한다. 2026-10-27 연결 계정에서 `gpt-6.1-sol` 기본값과 `gpt-6.1-terra`가 확인됐다. 모델을 임의로 추가하거나 API 키 과금으로 전환하지 않는다.
- `getStoreShortages`는 네이버 상품 동기화 캐시에서 상품 품절, 옵션 품절, 판매중지, 사용 중 옵션의 낮은 재고를 구분한다. 미확인 재고를 0으로 간주하지 않으며 동기화 경과 및 데이터 범위를 표시한다. 매장 실물 재고와는 별개다.
- `getStoreReorders`는 현재 브라우저에 저장된 재주문 목록을 조회한다. `prepareStoreReorder`는 품절 상품 전체 또는 정확한 옵션 추가, 수량·메모·완료 표시 변경, 항목 제거의 확인안을 만든다. 변경 대상은 같은 대화의 실제 조회 결과여야 하고, 저장 전 목록이 바뀌면 다시 확인하도록 한다. 실제 발주나 네이버 재고 수정은 하지 않는다.
- 재주문 데이터는 기존 `move-store-reorder-v1` localStorage를 사용하며 다른 브라우저·기기와 자동 공유되지 않는다. 확인 후 저장 결과를 재조회하고, 같은 화면의 상품 관리 목록에 변경 이벤트를 전달한다.
- `getStoreQuestions`는 기존 매장 PC의 읽기 전용 `bridge/store-care.mjs`를 통해 네이버 상품 문의를 조회한다. 문의 응답을 등록하지 않는다. 프로그램 실행이 필요하며, 기존 `Start-StoreCare.ps1` 사용; 자동 시작과 다른 기기 접근은 제공하지 않는다. 조회 실패를 0건으로 표시하지 않는다.
- `getStoreSettlements`는 같은 PC 연결의 네이버 일별 정산 API를 기간·페이지 단위로 조회한다. 정산예정일과 완료일을 보존하고 계좌정보는 반환하지 않는다. 조회 범위는 최대 94일이며, 부분 페이지의 합계를 전체로 주장하지 않는다. 부가세·건별 정산은 이번에 구현하지 않았다.
- GPT-6.1 Sol 실제 가상 데이터 대화에서 품절 옵션 조회 → 목록 추가 확인안 생성 성공, 저장 전 미변경을 검증했다. 네이버 문의 API는 기존 설정으로 최근 7일 미답변 조회, 일별 정산 API는 10월 1~26일 조회 성공. 쓰기 없음.
- 정산 조회는 수정된 `bridge/store-care.mjs`를 실행해야 한다. 이전 버전의 43128 연결이 이미 실행 중이면 기존 연결을 종료한 후 새 버전으로 실행해야 한다.
- 자동 회귀 테스트 204개 중 203 통과, 0 실패, 환경 의존 1 생략. 최종 Vite 빌드 57초 성공. 실제 모바일 기기와 스토어 정산 장기간 전체 대조는 검증하지 않았다.
