# 스토어 장바구니 → 예약·주문 채널 유지 점검

상태: 로컬 수정 및 검증 완료. 이번 변경은 아직 운영 배포하지 않음.

## 원인

- 주문 내역 카드는 주문 메모만으로 채널을 분류하고 거래처 목록을 전달하지 않아, 메모가 없는 스토어 고객 주문을 일반 카드로 표시했다.
- 주문 내역 → 저장 장바구니의 신규 저장·병합에서 원 주문 메모가 누락됐다.
- 저장 장바구니 → 주문확인 및 POS 불러오기에서도 메모가 누락됐다. 날짜가 아니라 이 전환 경로에서 출처가 소실됐다.
- 운영 거래처 화면에서 해당 고객이 엠파츠 카테고리에 등록된 것을 읽기 전용으로 확인했다. 운영 주문·고객 데이터는 변경하지 않았다.

## 변경

- `channelClassifier.js`: 거래처 ID 우선, ID가 없을 때 유일하게 정확히 일치하는 이름으로 고객 분류 확인. 이름 중복·부분일치로는 추정하지 않는다. 카드와 채널 집계에 동일한 분류 사용.
- `cartOrderContext.js`: 장바구니 전환 중 메모·가격 기준 보존. 고객을 변경하면 이전 고객의 메모를 자동 전달하지 않는다.
- 기존 스토어 고객의 메모 없는 주문도 네이버 카드로 표시한다. 이는 고객 카테고리에 따른 표시이며, 외부 주문 연결 복구와는 구분한다.
- 발송 버튼은 메모에서 외부 주문번호가 하나로 확인될 때만 노출한다. 외부 번호가 없거나 여러 주문번호가 병합됐으면 임의로 선택하지 않는다.
- 주문 저장 성공 뒤 장바구니를 삭제한다. 취소·실패 시 장바구니를 유지하고 중복 클릭을 차단한다.
- 저장된 명시적 0원 단가는 유지하고 단가가 누락된 경우에만 도매·소매 단가로 보완한다.

## 검증

- `node --test tests/*.test.mjs`: 184 통과 / 0 실패 / 1 생략(환경 의존 테스트).
- 신규 `store-cart-context.test.mjs`: 9 통과. 이름·ID 분류, 동명이인, 날짜가 지난 예약, 메모 전달, 고객 변경, 외부 번호 중복, 가격, 저장 성공·실패 순서 포함.
- `npm run build`: 성공. 기존 minify 설정·혼합 import·청크 크기 경고 유지.
- `git diff --check`: 통과.
- 개발 전용 `design-preview.html?storeCartCheck=1`: 기존 메모 없는 스토어 고객 카드와 일반 카드 비교. 어제 저장한 예약 장바구니의 실패 후 유지, 성공 후 삭제, 네이버 배지·외부 번호가 있는 카드의 발송 버튼 확인. 브라우저 오류 없음.
- 실제 네이버 발송이나 운영 주문 생성은 실행하지 않았다. 유실된 외부 주문번호를 고객명만으로 복구하지 않는다.
