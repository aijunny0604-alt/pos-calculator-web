# 버튼·명세서·입출금 점검 — 2026-10-15

## 적용 범위

앞선 디자인 배포 이후의 추가 로컬 수정이다. 이 문서의 수정은 아직 운영 배포하지 않았다. 운영 주문·입출금 자료와 DB 스키마는 변경하지 않았다.

## 수정한 문제

- [P1] 입출금/결제 레코드 삭제의 HTTP 실패가 성공으로 처리됨 → HTTP 상태와 반환된 삭제 행을 검사하고 화면도 실패 시 유지한다.
- [P1] 일괄 입금을 개별 요청으로 저장하며 반환 실패를 무시함 → 배열을 한 POST로 전달하고 모든 반환 행을 확인한다. 초과 입금액은 누락 저장 대신 입력 수정을 요구한다.
- [P1] 저장 결과가 불확실한 상태에서 재시도하면 중복 가능 → 등록/일괄 모달의 재저장을 막고 내역 새로고침을 안내한다. 동시 클릭에는 ref 잠금을 사용한다. 서버 차원의 멱등 키는 별도 과제다.
- [P2] 입금 수정의 UTC 문자열을 현지 datetime 입력에 직접 표시 → 현지 시간으로 변환하고, 시간을 수정하지 않으면 원본 초까지 보존한다.
- [P2] 거래처 전환 중 느린 이전 조회가 최신 선택을 덮음 → 이전 효과 응답을 무시하고 조회 중 저장을 막는다. 완납 건도 조회해 환불 대상을 선택할 수 있게 한다.
- [P2] 명세서 조회 실패가 빈 목록으로 표시됨 → 엄격 조회와 명시적 오류를 적용한다. 이전 날짜 조건 응답도 무시한다.
- [P2] +금액 버튼이 기존 금액을 교체함 → 표시대로 가산한다. 비정상/소수/안전 정수 초과 금액 및 부가 항목 오류를 차단한다.
- [P2] 업무 버튼 높이가 제각각임 → 일반 화면 40px, 모바일·터치 44px 최소 높이. 하단 주요 버튼 46px. 큰 카드형 버튼은 높이를 강제 축소하지 않는다.
- [P2] 360px 매입 발주 헤더의 직접 입력 버튼 잘림 → 헤더 줄바꿈과 작은 화면의 보조 안내 숨김으로 해소한다.

## 검증

- 단위 테스트: 86개 통과, 1개 환경 미지정으로 건너뜀.
- `tests/payment-ui.mjs`: 모의 HTTP 403/빈 삭제 결과/정상 삭제, 일괄 배열 요청, 초과 금액, 실패 상태 유지, 중복 클릭, 서울 시간 표시, 거래처 빠른 전환. 실제 외부 저장 요청 없음.
- `tests/design-audit.mjs`: PC 1366×768와 모바일 360×844의 17개 메뉴에서 화면 넘침·잘림 및 업무 버튼 최소 높이 검사. MOVIS 전용 버튼은 공통 크기 변경 대상에서 제외한다.
- `tests/design-modals.mjs`: 360/390/412/768/1024/1920px의 주요 모달 스크롤·포커스·버튼 검증.

## 남은 검증 범위

운영 DB의 현재 트리거 정의와 출금 부호 계산, 다중 PC 동시 입금의 잔액 잠금, 신규 명세서 생성+입금의 단일 트랜잭션, 서버 멱등성은 이번 모의 테스트로 검증하지 않았다. 문서의 자동 잔액 재계산 설명을 실제 DB 검증 완료로 해석하면 안 된다. 신규 명세서 생성 후 입금이 실패하면 명세서만 남을 수 있어 재조회 안내를 유지한다. 실제 Safari/모바일 키보드와 모든 데이터 조합도 미검증이다.

## 제품 주문 화면 제안

상품 목록+주문 목록 구조는 유지한다. PC 기본은 상품명·규격·재고·단가를 비교하는 목록형, 카드형은 선택형이 적합하다. 카테고리별 중첩 스크롤을 줄이고 거래처·가격 기준과 합계·저장을 고정한다. 최근 주문·즐겨찾기·이전 주문 복제, 모바일 주문 목록 전환이 우선 개선 대상이다. 큰 구조 변경은 이번 수정에 섞지 않았다.
