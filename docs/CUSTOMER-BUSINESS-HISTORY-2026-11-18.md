# 거래처 사업자 변경 이력

## 사용 흐름

거래처 관리 → 업체 상세 → 사업자 정보에서 상호·사업자번호·대표자·사업장 주소·업태·종목을 등록한다. 변경 시 `이전 정보 보존 후 저장`을 누르면 현재 정보가 변경되고 이전 정보는 변경일과 함께 이력에 남는다. 이전 사업자·등록증 보기에서 원본을 열 수 있다.

거래처 ID와 표시명은 자동으로 바꾸지 않는다. 기존 주문·입금·미수 원장도 변경하지 않는다. 사업자가 바뀌었다고 법적 채무나 거래 귀속이 이전되는 것으로 처리하지 않는다. 거래처를 별도 업체로 분리할 필요가 있는지는 사용자가 판단한다.

## DB 적용 순서

1. 운영 customers 스키마·정책과 업무 자료의 복구 가능한 백업을 확보한다.
2. `supabase/migrations/20261118_customer_business_history.sql`을 적용한다. customers에 프로필·변경 시각·횟수를 추가하고 별도 이력 테이블과 트리거를 만든다.
3. 구버전 프로그램도 등록증 원본 삭제 기능을 갖고 있으므로 다른 PC·휴대폰의 이전 버전을 종료·새로고침한 뒤 새 버전을 사용한다. DB 트리거는 파일 저장소의 물리 삭제까지 막지는 못한다.
4. 기존 고객 접근 정책과 연결된 이력 읽기 권한을 확인한다. 이력의 직접 INSERT/UPDATE/DELETE는 앱 역할에 허용하지 않는다. 이번 기능은 기존 공개 접근 문제를 해결하는 인증 도입이 아니다. SECURITY-SETUP.md를 함께 따른다.

## 보존과 동시 수정

- 고객 프로필 또는 등록증 연결 변경 시 DB 트리거가 이전 상태를 기록한다. 이력 저장 실패 시 현재 정보 변경도 롤백된다.
- 같은 값 재저장이나 연락처·표시명 등 다른 필드 수정은 사업자 이력을 만들지 않는다.
- 이미 등록된 문서만 있는 경우 문서 URL·경로·거래처 표시명을 보존한다. 과거 사업자번호를 추정하지 않는다. 기능 적용 전 삭제된 정보는 복구되지 않는다.
- 폼 저장은 편집을 시작할 때의 변경 시각을 검사해 다른 기기의 최신 변경을 덮어쓰지 않는다. 충돌·실패 시 초안은 유지한다.
- 등록증 교체·연결 해제·보관함 제거 시 이전 원본을 물리 삭제하지 않는다. 저장 응답이 불확실한 신규 파일도 임의 삭제하지 않는다. 저장소 용량은 증가할 수 있으며 파일 삭제는 이력 참조 확인 후 별도 관리해야 한다.
- 변경 이력은 업체 상세 진입·명시적 새로고침·저장 뒤에만 읽는다. 전역 거래처 조회에 이력 본문을 포함하거나 주기적으로 폴링하지 않는다.

## 검증

별도의 PGlite PostgreSQL에서 마이그레이션 재실행, 이전 정보·등록증의 원자적 보존, 실패 롤백, 비관련 필드 수정, 이력 직접 삭제 거부, 고객 RLS와 연동된 읽기 제한을 확인했다. 운영 데이터로 테스트하지 않았다.

`tests/customer-business.test.mjs`는 정규화·필수 항목·입력 길이를 확인한다. `tests/customer-business-ui.mjs`는 로컬 샘플 자료로 PC·모바일의 현재/이전 표시, 원본 링크, 동시 수정 충돌과 초안 보존을 확인한다. 실제 사업자 진위 확인이나 세무 검증 기능은 아니다.

`tests/customer-business-db.mjs`는 PGlite를 사용해 독립 DB에서 실행한다. 테스트 라이브러리는 운영 의존성에 추가하지 않으며, 별도 설치 후 `PGLITE_MODULE`에 모듈의 file URL을 지정해 실행할 수 있다.

## 적용 상태

2026-11-18 사용자가 현재 고객 자료와 동일한 이력 조회 범위 적용을 승인했다. 고객 323건을 로컬 비공개 파일로 백업하고 파일 저장 결과를 검증한 뒤 운영 DB에 마이그레이션을 적용했다. 고객 건수 323건 유지, 이력 테이블 RLS·변경 보존 트리거 활성화, 일반 역할의 이력 직접 INSERT/DELETE 권한 없음, 프로필·이력 API의 HTTP 200 응답을 확인했다. 실제 고객 사업자 정보를 시험 변경하지 않았다.

프런트엔드에는 이력 화면·등록증 원본 보존 경로를 함께 배포한다. 기존 고객 접근 정책을 통한 익명 조회 가능 상태는 유지되며, 이번 배포가 로그인/보안 전환 완료를 의미하지 않는다.

## 2026-11-19 표시 개선

- 사업자 정보가 비어 있으면 반복되는 ‘미등록’ 필드 대신 짧은 안내와 등록 버튼을 표시한다. 일부 정보만 있으면 입력된 항목만 보여준다.
- 현재 등록증의 원본 열기 버튼을 제공한다. 이전 이력의 이미지 등록증은 이력을 펼쳤을 때만 미리보기를 읽으며, 원본 열기와 접기를 지원한다. PDF 등은 원본 링크로 연다.
- 보존된 이력이 0건이면 그 사실을 명시한다. 첫 등록은 이전 정보가 없으므로 변경 이력을 만들지 않는다. 기능 적용 전 연결되지 않았던 사진이나 삭제된 파일을 새 이력처럼 추정해서 표시하지 않는다.
- 이력 보존 로직·접근 권한·기존 자료는 변경하지 않았다. 별도 운영 폴링이나 저장소 전수 조회도 추가하지 않았다.
- Chromium 로컬 샘플에서 너비 1440·768·390·360px의 현재/이전 정보, 사진만 있는 이력, 빈 상태 크기, 원본 링크, 이력 접기, 가로 넘침과 저장 충돌 시 초안 보존을 검증했다. 독립 PostgreSQL 호환 테스트에서 기존 보존·롤백·RLS 검증을 다시 통과했다. 실제 휴대폰 기기 검증은 하지 않았다.
