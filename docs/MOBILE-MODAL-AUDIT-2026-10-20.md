# 모바일 모달 점검 — 2026-10-20

## 범위

`src/pages`, `src/components`의 화면 전체 오버레이 선언 77곳을 검색해 모달 후보를 분류했다. 메뉴·배경 효과도 포함된 검색 결과이며 77개 모달을 모두 실제 실행했다는 뜻은 아니다. 높이 제한, 스크롤, 하단 내비게이션과의 레이어 관계를 코드로 점검하고 아래 대표 화면을 로컬 샘플 데이터로 실행했다. 실제 발송·취소·입출금 등록은 하지 않았다.

## 발견 및 수정

- [P1] 스마트스토어 발송 모달의 하단 버튼이 메뉴에 가림 → 페이지 내부 레이어와 하단 정렬, 화면 높이 처리 문제 → 등록 버튼 접근 불가. 화면 최상위 포털과 VisualViewport 높이를 적용하고 헤더·푸터를 유지하면서 본문만 스크롤하도록 수정했다. 자동 포커스도 제거했다.
- [P1] 명세서 대조의 닫기 버튼이 하단 메뉴에 가림 → 공통 페이지 진입 애니메이션의 `fill-mode: both`가 종료 후에도 stacking context를 유지 → 페이지 내부 모달의 높은 z-index가 하단 메뉴를 넘지 못함. `index.css`와 우선 적용되는 `move-design.css`의 중복 규칙을 모두 `backwards`로 수정했다. 애니메이션 자체는 유지한다.
- [P2] 방문수령·일괄 발송·주문 취소·연동 로그에 같은 레이아웃 위험 존재 → 발송과 동일한 화면 기준 모달을 적용했다.
- [P2] 명세서·입출금·거래처·매입 등 높이 제한에 고정 `vh` 사용 → 모바일 브라우저 주소창 변화와 실제 표시 높이가 어긋날 수 있음. 최대 높이의 단위를 `dvh`로 변경했다. 분석 모드 설정 본문과 스토어의 단순 확인창에는 스크롤을 보강했다.

브라우저는 Codex 내장 Chromium이다. 360×500은 높이가 줄어든 화면의 배치 테스트이며 실제 iOS 키보드 테스트를 대체하지 않는다. 실제 iPhone Safari/PWA, Android 키보드, 안전영역 인셋, 모든 업무 데이터 조합은 미검증이다. 입출금·매입 화면의 개별 저장 동작은 이번 UI 점검 범위에 포함하지 않았다.
